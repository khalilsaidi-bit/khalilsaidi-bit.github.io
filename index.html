SafeGuard IIoT

Semester project, École Polytechnique de Sousse · with Wassim Bergaoui · supervised by Mr. Khaled Ben Khlifa

Fire, heat and air-quality monitoring for a workshop, with an automatic ventilation flap and remote supervision in the cloud.

Demo on the real prototype (1 min 34, captions in French): start-up, telemetry, gas, temperature and fire alerts, remote control.

0.33 sfrom a dashboard command to the node's confirmation
100 msflame scan period, confirmed over 3 readings
5 stelemetry period over MQTT

What it does

  • An ESP32 reads an IR flame sensor, a DHT11 (temperature, humidity) and an MQ-135 gas sensor.
  • A state machine on the node decides: fire, heat alert, air-quality alert or normal. It drives a local alarm and a servo-driven ventilation flap.
  • Safety never depends on the network: if Wi-Fi or the broker goes down, detection and alarm keep running.
  • Telemetry and alerts go over MQTT to a Mosquitto broker in Docker. A Python gateway stores them in Firebase Realtime Database.
  • A Streamlit dashboard shows live values, trends and the alert log, and sends commands back to the flap.

Security

  • No anonymous access to the broker, one account per client, hashed passwords.
  • Credentials kept out of the code; closed Firebase rules, HTTPS only.
